## 전송 시작 지연 수정 · 콘텐츠 3

동일한 브라우저 조건에서 콘텐츠 2와 3을 비교했습니다. 태블릿 뷰포트 1280×800, 영상 1080p, 연결 1.17Mbps와 왕복 지연 125ms, 재생 속도 1배입니다.

| 검증 | 관측 |
|---|---|
| 콘텐츠 2 재현 | 과일 샐러드 첫 발화 지점 7.52초에 도달하기 전 0.87초, 2.58초, 5.38초에 버퍼링 발생 |
| 콘텐츠 3 시작 | 동일 조건에서 첫 발화까지 버퍼링 재발 0회. 약 5초 분량을 미리 읽고 재생 버튼을 표시 |
| 복구 | 테스트 미디어 응답에 HTTP 503을 주입한 뒤 재생 재시도, 첫 발화 안내와 계속 버튼을 거쳐 13초까지 진행 |
| 배포 | 기존 APK와 같은 JVM 복호화 코드로 GitHub의 목록 2 → 3 및 각 영상의 Range 응답 네 개 검증. 원격 번들의 HTML, CSS, JavaScript가 소스와 일치 |
| 휴대 기기 | 실제 갤럭시탭이 연결되지 않아 기기에서의 재현과 재확인은 미실행 |

검증 실행은 `python tests/startup.py <web 경로> <미디어 경로> after` 및 `python tests/startup.py <web 경로> <미디어 경로> retry injected`입니다. 이전 디렉터리를 `before`로 전달해 재현을 확인할 수 있습니다. `scripts/stream-encode.sh`로 가변 비트레이트의 1080p 스트림을 만듭니다.

같은 느린 연결에서 비눗방울 소동 첫 발화 6.76초와 사라진 빨간 공 첫 발화 25.04초까지 각각 재생했습니다. 시작 후 버퍼링은 두 영상 모두 0회였습니다. 최종 배포 코드로 세 편의 발화 정지 30곳과 1080p 재생을 브라우저에서 다시 통과했고, 세 파일을 FFmpeg로 끝까지 디코딩했습니다.
